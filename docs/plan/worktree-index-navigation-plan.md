# Worktree 序号与目录切换

## 问题与决策

`wk ls` 缺少便于输入的序号。未指定 `--all` 时增加 `#` 列，放在 `NAME` 前，从 1 开始，沿用现有列表顺序。指定 `--all` 时首列为 `REPO`，不显示序号，详细模式遵循相同规则。

- `wk <序号>` 复用默认 `ls` 命令的列表生成过程，输出对应路径，避免显示与选择使用不同的过滤或顺序。
- 序号只属于当前仓库，不允许与 `--all` 或 `-a` 组合使用。跨仓库列表只提供仓库名和路径。
- 保持无状态设计，不保存上一次列表。新增或删除 worktree 后，序号可能变化；按名称查询的 `wk path` 保持原意，包括纯数字名称。
- 二进制不能修改父 shell 的工作目录。README 提供 Zsh 包装函数，用户将其加入 `~/.zshrc`，由函数接收数字快捷命令、获取路径并调用内置 `pushd`。CLI 只负责列表和路径输出，无需初始化命令。
- Shell 函数只处理单个数字参数。其他命令和帮助参数透传给二进制。
- 只支持 Zsh，使用 `<->` 匹配数字、`[[ ... ]]` 判断参数组合。路径查询成功后才执行 `pushd`，保留失败退出码，用户可通过 `popd` 返回。

这次需求扩展了原 MVP 计划中不做 shell 集成的范围。保留 Git 操作封装和现有目录布局，不修改用户的 shell 配置。

## 风险与验收

- 序号越界、零、空列表须返回错误，不输出路径，shell 留在原目录。
- 当前仓库的普通和详细列表须在 `NAME` 前显示连续序号；跨仓库的普通和详细列表须显示 `REPO` 首列且不显示序号。路径选择须匹配对应列表顺序。
- wk 和 Codex 两种布局都须可选；路径包含空格时须正确切换。
- Zsh 中 `wk 1`、`wk 2` 须改变当前 shell 的目录并保留目录栈；`wk ls`、`wk path`、帮助须正常透传。数字与 `--all` 或 `-a` 组合时返回错误，当前目录不变。
